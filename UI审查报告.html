高危问题 页面错乱 / 交互 Bug / 安全漏洞

高危 admin.html innerHTML 注入 XSS 风险
public/admin.html · 第 485-489 行

使用申请列表渲染时，r.email 直接拼入 innerHTML，未经 HTML 转义。虽然服务端有正则校验，但攻击者可能通过其他途径注入包含 HTML 标签的邮箱。

恶意邮箱可注入 <script> 或 <img onerror>，后台管理员浏览即触发 XSS。
所有动态数据插入 DOM 前必须转义，或使用 textContent / createElement 替代 innerHTML 拼接。
function esc(s) {
  return String(s||'').replace(/[<>"']/g, m =>
    ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[m]));
}
// 使用： '<span class="r-mail">' + esc(r.email) + '</span>'
高危 访客列表 innerHTML 注入风险
public/admin.html · 第 865-871 行

访客列表渲染时 maskIp(v.ip)、region、v.device 直接拼入 innerHTML。虽然这些字段由服务端计算，但 region 来源于 cf.city 原始值经映射表转换，若映射表中未覆盖的城市名直接回传则可能注入。

服务端数据被篡改或映射遗漏时，可在后台注入任意 HTML。
统一使用 esc() 函数对所有动态数据进行 HTML 转义后再插入。
高危 d.error 直接注入 innerHTML
public/admin.html · 第 473 行

list.innerHTML = '...' + (d.error || '加载失败') + '...' 直接将 API 返回的 error 字段注入 HTML。如果 error 中包含 HTML 标签会被直接执行。

服务端异常信息中若包含用户可控数据，可导致 XSS。
对 d.error 同样使用 esc() 转义，或使用 textContent 设置错误信息。
高危 前台 viewport 禁止缩放，无障碍违规
public/index.html · 第 5 行

user-scalable=no, maximum-scale=1.0 禁止用户缩放页面，违反 WCAG 1.4.4 无障碍标准。视力障碍用户无法放大文字查看内容。

无障碍合规性问题，部分国家和地区法规要求不允许禁止缩放。
移除 user-scalable=no, maximum-scale=1.0，改用 JS 手势拦截仅对图片区域生效。
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
高危 index.html 图片 onerror 无限重试风险
public/index.html · 第 574-578 行

图片加载失败时 img.src = img.src 会触发重新加载，虽然有 dataset.r 防重复，但如果 CDN 返回 200 但内容损坏，浏览器不会触发 onerror，会导致永远显示破图且无重试。

CDN 故障时用户看到持续破损的图片，无任何提示或兜底 UI。
增加加载超时检测和破图占位 UI，设置最大重试次数。

中风险问题 体验不一致 / 样式割裂

中风险 三页面颜色体系完全割裂
index.html / admin.html / thanks.html

三个页面各自硬编码不同色值，无统一设计 Token：

- index.html 背景 #f5f5f7，主色 #4a7dff（蓝色偏紫）
- admin.html 背景 #f2f3f7，主色 #1d1d1f（纯黑）
- thanks.html 背景渐变 #fafbfd→#eceff4，主色 #007aff（系统蓝）

提取为 CSS 变量 :root { --color-primary: #007aff; --color-bg: #f5f5f7; ... }，三页面共用。
中风险 字体栈不统一，三套不同 font-family
index.html 第 11 行 / admin.html 第 11 行 / thanks.html 第 12-13 行

三页面 font-family 声明不一致：index.html 缺少 "WenQuanYi Micro Hei"，thanks.html 额外包含 "SF Pro SC"、"SF Pro Text"、"Segoe UI"，admin.html 最简。在 Linux 系统上可能出现不同页面字体回退差异。

统一为同一字体栈，建议提取为 CSS 变量 --font-sans。
中风险 圆角、间距、阴影无规范
全文件

圆角值在不同页面和组件间不一致：卡片圆角 admin=14px / thanks=22px / index 无圆角；按钮圆角 admin=8px / thanks=13px / index=6px。间距也随意：admin 卡片 padding=22px 24px，thanks 卡片无统一 padding。

建立间距和圆角 Token：--radius-sm: 8px; --radius-md: 12px; --radius-lg: 16px; --space-card: 22px 24px;
中风险 admin.html 密码输入框未统一样式
public/admin.html · 第 353-354 行

修改密码页面的两个 input 使用内联 style 硬编码样式（style="flex:1;padding:9px 12px;border:1px solid #d9d9de;..."），与 .form-row input[type=text] 的 class 样式定义完全重复，是典型的复制粘贴。

统一使用 class 样式，移除内联 style。
中风险 重复 SVG 图标代码未封装
index.html / admin.html

关闭按钮 SVG（M19 6.41 17.59 5...）在 index.html 出现 2 次，admin.html 出现 0 次但使用了 emoji（👁/🚫/↑/↓）作为操作按钮图标，风格不统一。thanks.html 使用了 15+ 个独特 SVG 但每个都只内联一次。

提取公共 SVG 为 JS 常量或 <symbol> + <use>，减少重复代码。
中风险 admin.html 无操作反馈统一性
public/admin.html

不同操作的反馈方式不一致：保存设置显示 "已保存 ✓"（绿色 .ok-msg）；删除申请无任何提示，直接 remove DOM 行；二维码上传显示文字状态；PDF 上传显示进度条 + 文字。缺乏统一的 Toast/通知组件。

封装轻量 Toast 组件，统一所有操作反馈为：成功(绿) / 失败(红) / 进行中(灰) 三态。
中风险 z-index 层级混乱无规范
public/index.html

index.html z-index 分布：loading=2000, lightbox=3000, qr-modal=1500, phone-pop=1100, contact-dock=1000, page-footer=900, lightbox内部按钮=2。数值随意，无层级分组，loading(2000) 低于 lightbox(3000) 但高于 qr-modal(1500)，逻辑上 loading 应为最高层。

定义 z-index 层级 Token：base(1) / dock(100) / popover(200) / modal(300) / loading(400) / lightbox(500)。
中风险 admin.html 删除操作无二次确认
public/admin.html · 第 497-505 行

使用申请的删除按钮直接调用 DELETE API 并移除行，无确认弹窗。误点击会直接删除数据且不可恢复。

添加 confirm('确定删除此申请？') 或自定义确认弹窗。
中风险 admin.html 按钮防重复提交不完整
public/admin.html

保存设置按钮有 disabled 防重复（第 525 行），但 PDF 上传按钮的 disabled 状态在 catch 块中也会执行，如果请求途中网络断开，按钮可能保持 disabled 直到超时。二维码上传按钮同理。删除申请按钮 disabled=true 后在 catch 中未恢复。

在 finally 块中统一恢复按钮状态，删除按钮需要在 catch 中恢复 disabled=false。

低风险优化 规范 / 可维护性 / 细节

低风险 大量内联 style 滥用
index.html（6处）/ admin.html（12+处）

index.html 中 style="display:none" 出现在 watermark、dock、phone-pop、qr-modal 等元素上。admin.html 更严重：密码输入框、二维码区域、按钮 padding 等大量使用内联 style，业务逻辑与样式混写。

将内联 style 迁移为 class，使用 .hidden { display: none; } 等工具类。
低风险 backdrop-filter 重复代码 5+ 处
public/index.html

backdrop-filter: blur(16px) saturate(1.8); -webkit-backdrop-filter: blur(16px) saturate(1.8); 在 .page-footer .text、.contact-dock .cbtn、.phone-card、.lb-page、.lb-btn 等 5 处完全重复。

提取为 .frosted { backdrop-filter: blur(16px) saturate(1.8); -webkit-backdrop-filter: blur(16px) saturate(1.8); } 工具类。
低风险 admin.html 登录按钮文案用字存疑
public/admin.html · 第 204 行、445 行

按钮文案为 "登 录"，字符间有空格。虽然不影响功能，但与其他按钮文案（"保存设置"、"上传替换"）风格不一致，空格显得突兀。

移除空格改为 "登录"，与其他按钮文案保持一致。
低风险 admin.html 小屏幕 tab 可能溢出
public/admin.html · 第 62-63 行

tabs 容器设置了 flex-wrap: wrap，在 320px 以下屏幕上 6 个 tab 按钮会换行成 3-4 行，占用较多垂直空间。

在小屏幕上改为水平滚动：@media (max-width:480px) { .tabs { overflow-x: auto; flex-wrap: nowrap; } }
低风险 无 CSS 变量 / 设计 Token 体系
全项目

所有颜色、圆角、间距均为硬编码值（如 #4a7dff、#1d1d1f、#86868b），无 :root 变量定义。主题色修改需要全局搜索替换。

建立 :root CSS 变量体系，至少包含主色、背景色、文字色、圆角、间距 5 组 Token。
低风险 admin.html emoji 图标与 SVG 风格混用
public/admin.html · 第 724-728 行

页面管理操作按钮使用 emoji（👁/🚫/↑/↓），但其他页面使用 SVG 图标。emoji 在不同平台渲染不一致（Windows/iOS/Android 外观差异大），影响一致性。

统一使用 SVG 图标，替换 emoji 为线条式 SVG。
低风险 文案用词不统一
全项目

thanks.html 用 "获取同款"，index.html 无对应文案；admin.html "保存设置" vs "保存页面设置" vs "修改密码" vs "上传替换"，动词不统一。thanks.html 表单用 "提交"，index.html 无独立表单。

统一按钮文案规范：保存类用"保存XX"，上传类用"上传XX"，修改类用"修改XX"。
低风险 无 i18n 国际化支持
全项目

所有文案硬编码中文（"正在加载…"、"保存中…"、"上传完成 ✓"等），无法适配多语言场景。如果后续需要英文版需要全局重构。

当前项目为个人作品集，i18n 优先级低。如需扩展，建议引入轻量 i18n key-value 映射。
