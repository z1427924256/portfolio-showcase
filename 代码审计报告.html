高危问题（必须修复）

高危admin.html innerHTML XSS 注入（3 处）
public/admin.html · 第 473、485-489、865-871 行

r.email、d.error、maskIp(v.ip)、region、v.device 直接拼入 innerHTML，未经 HTML 转义。

恶意邮箱或服务端异常数据可注入任意 HTML/JS，管理员浏览后台即触发 XSS。

【直接替换】所有动态数据经过 esc() 转义后再插入 innerHTML，或改用 textContent + createElement。
高危admin.html 删除申请无二次确认
public/admin.html · 第 497-505 行

.r-del 按钮点击后直接发 DELETE 请求，无确认弹窗，误点击立即删除且不可恢复。

管理员误点击导致数据永久丢失。

【添加确认】在 DELETE 请求前添加 if (!confirm('确定删除此申请？')) return;
高危admin.html 删除按钮 catch 块未恢复 disabled
public/admin.html · 第 500-504 行

b.disabled = true 在 try 块中设置，但 catch 块为空 catch (err) {}，请求失败后按钮永久 disabled。

API 报错后删除按钮永久不可点击，管理员无法重试。

【添加 finally】catch 块中添加 b.disabled = false;
高危index.html viewport 禁止缩放（无障碍违规）
public/index.html · 第 5 行

user-scalable=no, maximum-scale=1.0 禁止用户缩放，违反 WCAG 1.4.4。

视障用户无法放大文字，部分国家法规不允许禁止缩放。

【直接删除】移除 user-scalable=no, maximum-scale=1.0, minimum-scale=1.0。
高危upload.js kv_to_r2 / kv_list 引用已移除的 env.FILES
functions/api/upload.js · 第 30-55 行

wrangler.toml 已移除 KV 绑定，但 upload.js 中 kv_to_r2 和 kv_list 两个分支仍引用 env.FILES。KV 未绑定时 env.FILES 为 undefined，调用 .getWithMetadata() 会抛 TypeError。

管理员误触发迁移功能时返回 500 错误。

【直接删除】移除 kv_to_r2 和 kv_list 两个死代码分支，KV 已移除，迁移功能不再需要。
高危_lib.js saveFile 注释与实现不一致
functions/_lib.js · 第 88-99 行

注释写"双写 R2 + KV"，但项目已移除 KV 绑定。saveFile 中 env.FILES 为 undefined 时走 Promise.reject，虽然 allSettled 不会崩，但每次写入都会产生一个 rejected promise，浪费资源。

每次文件写入产生不必要的 rejected promise，日志噪音。

【优化代码】将 saveFile 简化为仅写 R2，删除 KV 双写逻辑。

中风险问题

中风险track.js 频率限制查询缺少索引
functions/api/track.js · 第 96 行

SELECT ts FROM visits WHERE ip=? ORDER BY ts DESC LIMIT 1 — schema.sql 已有 idx_visits_ip(ip, ts) 索引，覆盖此查询。确认通过。

无风险，索引已覆盖。（标记为验证通过）

中风险stats.js 7 个并发 D1 查询无边缘缓存
functions/api/stats.js · 第 22-39 行

虽然已有 30 秒内存缓存，但首次请求或 Worker 实例冷启动时仍会并发 7 个 D1 查询。D1 免费版并发数有限。

D1 限流时统计页面超时。

【可选优化】添加 Cloudflare 边缘缓存 cache.put(request, res.clone())，TTL 30 秒。
中风险config.js JSON.parse 无 try-catch
functions/api/config.js · 第 25-27 行

JSON.parse(map.site_config) 等三处 JSON.parse 无异常处理。如果数据库中存储了损坏的 JSON 字符串，会抛未捕获异常导致 500。

数据库数据损坏时整个配置 API 崩溃。

【添加 try-catch】包裹 JSON.parse，异常时返回空对象默认值。
中风险upload.js pages_manifest JSON.parse 无 try-catch
functions/api/upload.js · 第 77-80 行

JSON.parse(form.get('manifest') || 'null') 已有 try-catch（第 76-80 行），确认通过。

中风险upload.js pages_prev 版本比较逻辑缺陷
functions/api/upload.js · 第 111 行

prevOld.version !== version && prevOld.version !== (cur && cur.version) — 当首次上传时 cur 为 null，cur.version 会短路为 undefined，逻辑正确。但 prevOld.version !== (cur && cur.version) 在 cur 为 null 时等价于 prevOld.version !== undefined 恒为 true，可能导致旧版数据被误删。

极端边界条件（首次上传后立即第二次上传）可能误删上一版图片。

【添加 null 检查】改为 prevOld.version !== version && (!cur || prevOld.version !== cur.version)。
中风险file/[[path]].js PDF 流未设置背压控制
functions/api/file/[[path]].js · 第 168-191 行

ReadableStream 的 pull 函数同步加载 R2 chunk 并 enqueue，如果客户端读取慢，内存中可能积压多个 20MB chunk。

大 PDF + 慢客户端可能导致 Worker 内存超限（128MB）。

【可选优化】添加 controller.desiredSize 检查，控制预加载量。
中风险auth.js 动态 import 性能浪费
functions/api/auth.js · 第 36 行

const { getSecret } = await import('../_lib'); — getSecret 已在 _lib.js 中 export，但 auth.js 顶部未导入，而是在运行时动态 import。每次登录多一次模块解析开销。

登录请求多一次动态 import 开销。

【直接修复】顶部 import 中添加 getSecret，移除动态 import。
中风险index.html 图片 onerror 重试无退避上限
public/index.html · 第 574-578 行

img.dataset.r = '1' 防止多次重试，但如果 CDN 返回 200 但内容损坏（空响应），浏览器不会触发 onerror，破图永久显示。

CDN 故障时用户看到永久破图，无兜底 UI。

【可选优化】添加 onload 超时检测，破图时显示占位文案。
中风险thanks.html viewport 也禁止缩放
public/thanks.html · 第 5 行

与 index.html 同样的问题：user-scalable=no, maximum-scale=1.0。

【直接删除】移除缩放限制。
